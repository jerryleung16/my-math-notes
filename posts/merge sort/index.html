1. Algorithm Design Approaches

Algorithms can be designed using various fundamental approaches. Two primary techniques are:

  • Incremental Approach: Used by algorithms like Insertion Sort. It builds the solution one element at a time (e.g., inserting a single element into an already sorted subarray).
  • Divide-and-Conquer Approach: A highly recursive alternative that often yields significantly faster worst-case running times. It solves problems by breaking them down into smaller, manageable pieces.

2. The Divide-and-Conquer Paradigm

This recursive approach involves three distinct steps at each level of the recursion:

  1. Divide: Break the original problem into a number of smaller subproblems that are just smaller instances of the exact same problem.
  2. Conquer: Solve the subproblems recursively. However, if the subproblem size is small enough (the recursion “bottoms out”), solve it in a straightforward, direct manner.
  3. Combine: Merge the solutions of the smaller subproblems together to formulate the solution to the original, overarching problem.

3. Merge Sort Overview

Merge Sort is a classic algorithm that strictly follows the divide-and-conquer paradigm to sort a sequence of elements:

  • Divide: Split the sequence into two separate subsequences of equal (or near-equal) size.
  • Conquer: Recursively sort both subsequences using Merge Sort. This process bottoms out when a sequence hits a length of 1, as a single element is already inherently sorted.
  • Combine: Merge the two sorted subsequences back together to produce the final, fully sorted answer.

The Brief Idea: The algorithm works by recursively tracing the array indices all the way down to the base cases (single elements) first, and only then performs the merging process on the way back up the call stack.

4. The MERGE-SORT Pseudocode

To sort an array, we need a function that drives the divide-and-conquer process.

Line MERGE-SORT(A, p, r)
1 if \(p < r\)
2     \(q = \lfloor(p + r)/2\rfloor\)
3     MERGE-SORT(A, p, q)
4     MERGE-SORT(A, q + 1, r)
5     MERGE(A, p, q, r)

To sort an entire sequence \(A = \langle A[1], A[2], \dots, A[n] \rangle\), we make the initial call MERGE-SORT(A, 1, A.length). The algorithm consists of repeatedly merging pairs of smaller sorted sequences to form larger ones until the final sorted sequence is formulated.

5. Concrete Example: Tracing MERGE-SORT

Let us trace the overarching MERGE-SORT logic on a 4-element array to see how it traces indices before merging.

Initial Array: [5, 2, 4, 1]

Function Call Condition Action / Result
MERGE-SORT(A, 1, 4) if 1 < 4 (ok) \(q = \lfloor(1 + 4)/2\rfloor = 2\)
    MERGE-SORT(A, 1, 2) if 1 < 2 (ok) \(q = \lfloor(1 + 2)/2\rfloor = 1\)
        MERGE-SORT(A, 1, 1) if 1 < 1 (no) end
        MERGE-SORT(A, 2, 2) if 2 < 2 (no) end
    MERGE(A, 1, 1, 2) Array \(A\) becomes [2, 5, 4, 1]
    MERGE-SORT(A, 3, 4) if 3 < 4 (ok) \(q = \lfloor(3 + 4)/2\rfloor = 3\)
        MERGE-SORT(A, 3, 3) if 3 < 3 (no) end
        MERGE-SORT(A, 4, 4) if 4 < 4 (no) end
    MERGE(A, 3, 3, 4) Array \(A\) becomes [2, 5, 1, 4]
MERGE(A, 1, 2, 4) Array \(A\) becomes [1, 2, 4, 5]

## 6. The MERGE Procedure

The crucial operation in Merge Sort is the “combine” step, handled by an auxiliary procedure called MERGE(A, p, q, r).

  • Function: It assumes that the two subarrays \(A[p \dots q]\) and \(A[q+1 \dots r]\) are already sorted. It merges them into a single sorted subarray that replaces \(A[p \dots r]\).
  • Card Analogy: Imagine two sorted piles of cards face up on a table. You compare the top two cards, remove the smaller one, and place it face down in a new output pile. You repeat this constant-time comparison step until all cards are merged.
  • Time Complexity: Because each basic step compares two cards and takes constant time, merging \(n\) total elements takes \(\Theta(n)\) time.
  • Sentinels: To prevent the algorithm from constantly needing to check if either pile is completely empty, a special “sentinel” card containing the value infinity (\(\infty\)) is placed at the bottom of each pile. This guarantees that the core sorting logic stops exactly when all real data has been merged.

7. MERGE Pseudocode

Below is the pseudocode for the merging process, demonstrating the use of the new temporary arrays (\(L\) and \(R\)) and the sentinel values.

Line MERGE(A, p, q, r)
1 \(n_1 = q - p + 1\)
2 \(n_2 = r - q\)
3 let \(L[1 \dots n_1 + 1]\) and \(R[1 \dots n_2 + 1]\) be new arrays
4 for \(i = 1\) to \(n_1\)
5     \(L[i] = A[p + i - 1]\)
6 for \(j = 1\) to \(n_2\)
7     \(R[j] = A[q + j]\)
8 \(L[n_1 + 1] = \infty\)     // Sentinel value
9 \(R[n_2 + 1] = \infty\)     // Sentinel value
10 \(i = 1\)
11 \(j = 1\)
12 for \(k = p\) to \(r\)
13     if \(L[i] \le R[j]\)
14         \(A[k] = L[i]\)
15         \(i = i + 1\)
16     else \(A[k] = R[j]\)
17         \(j = j + 1\)

Understanding the MERGE(A, p, q, r) Procedure

To understand exactly how this pseudocode works, let’s trace it using a concrete example.

Our Setup

Imagine we have an array \(A\) (using 1-based indexing, as the textbook does):

\[ A = [8, 4, 7, 2, 5, 9] \]

We want to merge two sorted sections in the middle of this array:

  • The left sorted pile: \([4, 7]\) (located at indices 2 and 3)
  • The right sorted pile: \([2, 5]\) (located at indices 4 and 5)

We call MERGE(A, 2, 3, 5). Here, \(p = 2\) (start), \(q = 3\) (middle), and \(r = 5\) (end).

Part 1: Figuring Out the Sizes

  • Line 1: \(n_1 = q - p + 1\)
    • Math: \(n_1 = 3 - 2 + 1 = 2\)
    • Meaning: We calculate the number of elements in the left pile. The left pile has 2 elements (\([4, 7]\)).
  • Line 2: \(n_2 = r - q\)
    • Math: \(n_2 = 5 - 3 = 2\)
    • Meaning: We calculate the number of elements in the right pile. The right pile has 2 elements (\([2, 5]\)).

Part 2: Creating the Left and Right Piles

  • Line 3: let L[1 .. n_1 + 1] and R[1 .. n_2 + 1] be new arrays
    • Meaning: We create two empty temporary arrays, \(L\) (Left) and \(R\) (Right). We make them one slot bigger than \(n_1\) and \(n_2\) (size 3) to make room for the special “sentinel” card at the bottom.
  • Lines 4–5: for \(i = 1\) to \(n_1 \implies L[i] = A[p + i - 1]\)
    • Meaning: Copy the left sorted section from array \(A\) into our new array \(L\).
    • When \(i = 1\): \(L[1] = A[2 + 1 - 1] = A[2] = 4\)
    • When \(i = 2\): \(L[2] = A[2 + 2 - 1] = A[3] = 7\)
    • Result: \(L = [4, 7, ?]\)
  • Lines 6–7: for \(j = 1\) to \(n_2 \implies R[j] = A[q + j]\)
    • Meaning: Copy the right sorted section from array \(A\) into our new array \(R\).
    • When \(j = 1\): \(R[1] = A[3 + 1] = A[4] = 2\)
    • When \(j = 2\): \(R[2] = A[3 + 2] = A[5] = 5\)
    • Result: \(R = [2, 5, ?]\)
  • Lines 8–9: \(L[n_1 + 1] = \infty\) and \(R[n_2 + 1] = \infty\)
    • Meaning: Place the sentinel value (infinity) at the end of both temporary arrays. This acts as a wall so we never run out of bounds during comparison.
    • Result: \(L = [4, 7, \infty]\) and \(R = [2, 5, \infty]\)

Part 3: The Merging Process

  • Lines 10–11: \(i = 1\) and \(j = 1\)
    • Meaning: We set our “pointers”. \(i\) points to the top card of the Left pile (\(L[1] = 4\)). \(j\) points to the top card of the Right pile (\(R[1] = 2\)).
  • Lines 12–17: for \(k = p\) to \(r\)
    • Meaning: This is the main loop. We will look at the slots in the original array \(A\) from index \(p = 2\) to \(r = 5\), and figure out which number goes there by comparing the tops of piles \(L\) and \(R\).
Loop Iterations
  1. Loop Iteration 1 (\(k = 2\)):
    • Compare (Line 13): Is \(L[1]\) (which is \(4\)) \(\le R[1]\) (which is \(2\))? No.
    • Action (Lines 16–17): The right card is smaller. Put \(R[1]\) into the main array at \(A[2]\). Move the right pointer down (\(j = 2\)).
    • Array \(A\) is now: \([8, 2, 7, 2, 5, 9]\)
  2. Loop Iteration 2 (\(k = 3\)):
    • Compare (Line 13): Is \(L[1]\) (which is \(4\)) \(\le R[2]\) (which is \(5\))? Yes.
    • Action (Lines 14–15): The left card is smaller. Put \(L[1]\) into the main array at \(A[3]\). Move the left pointer down (\(i = 2\)).
    • Array \(A\) is now: \([8, 2, 4, 2, 5, 9]\)
  3. Loop Iteration 3 (\(k = 4\)):
    • Compare (Line 13): Is \(L[2]\) (which is \(7\)) \(\le R[2]\) (which is \(5\))? No.
    • Action (Lines 16–17): The right card is smaller. Put \(R[2]\) into the main array at \(A[4]\). Move the right pointer down (\(j = 3\)).
    • Array \(A\) is now: \([8, 2, 4, 5, 5, 9]\)
  4. Loop Iteration 4 (\(k = 5\)):
    • Compare (Line 13): Is \(L[2]\) (which is \(7\)) \(\le R[3]\) (which is \(\infty\))? Yes. (This is why the sentinel is genius! Any real number is less than \(\infty\), so it forces the remaining cards in \(L\) to be picked up).
    • Action (Lines 14–15): The left card is smaller. Put \(L[2]\) into the main array at \(A[5]\). Move the left pointer down (\(i = 3\)).
    • Array \(A\) is now: \([8, 2, 4, 5, 7, 9]\)

Conclusion

The loop finishes because \(k\) reached \(r = 5\).

Our original array \(A\) went from \([8, 4, 7, 2, 5, 9]\) to \([8, 2, 4, 5, 7, 9]\).

The target section from indices 2 through 5 is now perfectly merged and sorted!

8. Concrete Example: Tracing Merge Sort

To understand how Merge Sort operates in practice, let us trace the algorithm on an unsorted 8-element array:

\[ A = [5, 2, 4, 7, 1, 3, 2, 6] \]

Step 1: The Divide Phase

The algorithm recursively splits the array in half until every subsequence contains only a single element:

  • Split 1: \([5, 2, 4, 7]\) and \([1, 3, 2, 6]\)
  • Split 2: \([5, 2]\), \([4, 7]\), \([1, 3]\), and \([2, 6]\)
  • Base Case (Length 1): \([5]\), \([2]\), \([4]\), \([7]\), \([1]\), \([3]\), \([2]\), and \([6]\)

At this point, the recursion bottoms out because sequences of length 1 are trivially sorted.

Step 2: The Combine Phase (Merging)

The auxiliary procedure MERGE combines the small sorted subarrays back together level-by-level:

  • Merge to size 2: \([2, 5]\), \([4, 7]\), \([1, 3]\), and \([2, 6]\)
  • Merge to size 4: \([2, 4, 5, 7]\) and \([1, 2, 3, 6]\)
  • Final Merge to size 8: We call MERGE on the two halves \(L = [2, 4, 5, 7]\) and \(R = [1, 2, 3, 6]\).
