Introduction to Object-Oriented Programming with Python

Welcome to the world of Object-Oriented Programming (OOP)!

The name may sound complicated, but the basic idea is quite simple: OOP is a way of organizing programs by modeling things as objects, similar to the way we think about objects in the real world.

A helpful way to understand OOP is to imagine a cookie cutter.

  • A Class is the cookie cutter. It is a blueprint or template that describes what something should look like and what it can do. You cannot eat the cookie cutter, but it determines the shape of every cookie you make.
  • An Object is the cookie. It is an actual thing created from the class. One cookie cutter can be used to make many different cookies.

For example, one Dog class can be used to create many different dog objects:

Dog class
   ↓
 ┌─────────┬─────────┬─────────┐
 ↓         ↓         ↓
Buddy     Daisy     Max

Each object follows the same blueprint but can have its own data.

The 4 Key OOP Vocabulary Words

Before writing code, let’s learn four terms that you will encounter constantly when working with classes.

Term Simple Meaning Real-World Example
Class A blueprint or template for creating objects. The general idea of a “Dog”
Object (Instance) A specific item created from a class. Your pet dog, Fido
Attribute Data stored inside an object that describes it. Name, breed, age, fur color
Method A function inside a class that describes an action. Barking, sitting, fetching

A useful way to remember the difference is:

Attributes describe what an object has. Methods describe what an object can do.

Building Our First Class

Let’s turn the general idea of a Dog into Python code.

We want our Dog class to have:

  • Attributes: a name and an age
  • Method: the ability to bark
class Dog:

    # The constructor: used to initialize a new object
    def __init__(self, name, age):
        self.name = name
        self.age = age

    # A method: an action the dog can perform
    def bark(self):
        print(f"{self.name} says Woof!")

Breaking Down the Code

Let’s examine the code one piece at a time.

1. class Dog:

class Dog:

This tells Python:

“I want to create a new blueprint called Dog.”

By convention, Python class names usually begin with a capital letter.

2. def __init__(self, name, age):

def __init__(self, name, age):

__init__ is a special method called the constructor.

It runs automatically whenever we create a new object from the class.

The constructor allows us to provide the initial information needed to set up our object.

For example:

Dog("Buddy", 3)

Python uses "Buddy" as the name and 3 as the age when setting up the new dog.

3. self.name = name

self.name = name
self.age = age

The keyword self refers to the particular object currently being created or used.

So:

self.name = name

can be understood as:

“Take the name provided by the user and store it as the name of this specific dog.”

Similarly:

self.age = age

means:

“Store this age as the age of this specific dog.”

4. def bark(self):

def bark(self):
    print(f"{self.name} says Woof!")

This is a function defined inside a class, so we call it a method.

The method also receives self because the dog needs to know which dog is performing the action.

Bringing the Class to Life

Our class is only a blueprint so far.

Now let’s use it to create actual objects.

# Create the first dog
dog_1 = Dog("Buddy", 3)

# Create a second dog
dog_2 = Dog("Daisy", 5)

We have now created two separate objects:

  • dog_1 represents Buddy, who is 3 years old.
  • dog_2 represents Daisy, who is 5 years old.

Both objects were created from the same Dog class, but each object has its own data.

Accessing Attributes and Methods

We can interact with an object using the dot operator (.).

Accessing Attributes

print(dog_1.name)
# Buddy

print(dog_2.age)
# 5

The dot tells Python which attribute belonging to the object we want to access.

Calling Methods

dog_1.bark()
# Buddy says Woof!

dog_2.bark()
# Daisy says Woof!

Notice how the same method can produce different results depending on the object that calls it.

This is one of the key ideas behind OOP.

Why Do We Use Classes?

For a very small program, you may not need classes.

For example, if you are writing a quick program to calculate your taxes, a class might be unnecessary.

However, as programs become larger—such as:

  • video games,
  • web applications,
  • data dashboards,
  • simulations, or
  • business software,

classes can make your code much easier to organize.

Imagine a video game with two players.

Without classes, you might have variables such as:

player_1_health
player_1_score
player_2_health
player_2_score

As the game becomes more complicated, you could end up with dozens or even hundreds of related variables.

Instead, we can create a Player class and then create multiple player objects from it.

Player class
      ↓
 ┌────┴────┐
 ↓         ↓
Player 1  Player 2

Each player object can keep track of its own health, score, name, and other information.

A class lets us organize related data and actions into one reusable structure.

Understanding self

The keyword self is one of the most important concepts for beginners learning Python classes.

Think of a class as a blueprint for building robots.

Suppose we use the blueprint to build two robots:

Robot class
     ↓
 ┌───┴────┐
 ↓        ↓
Wall-E   R2-D2

Both robots are built from exactly the same blueprint.

However, if we ask Wall-E to introduce itself, we want Wall-E to give its name—not R2-D2.

In Python, self means:

“this particular object”

or, more casually:

“me” / “my”

Let’s see this in action.

class Robot:

    # self.name means "MY name"
    def __init__(self, name):
        self.name = name

    # self.name means "MY name"
    def introduce(self):
        print(f"Hello, my name is {self.name}.")


# Create two different robot objects
robot_1 = Robot("Wall-E")
robot_2 = Robot("R2-D2")


robot_1.introduce()
# Hello, my name is Wall-E.

robot_2.introduce()
# Hello, my name is R2-D2.

Even though both robots use exactly the same class definition, each object stores its own name.

robot_1.name → "Wall-E"
robot_2.name → "R2-D2"

That’s the power of self.

What Happens If You Forget self?

One of the most common mistakes beginners make is forgetting self when defining a method.

Consider this example:

class Robot:

    # Oops! We forgot self.
    def beep():
        print("Beep boop!")


my_robot = Robot()
my_robot.beep()

Python will produce an error similar to:

TypeError: Robot.beep() takes 0 positional arguments but 1 was given

At first, this error can seem strange.

You might think:

“I didn’t give beep() any arguments! The parentheses are empty!”

So where did the mysterious 1 argument come from?

Python Is Doing Something Behind the Scenes

When you write:

my_robot.beep()

Python effectively treats this as:

Robot.beep(my_robot)

In other words, Python automatically passes the object that called the method as the first argument.

That object needs somewhere to go.

That is why we write:

def beep(self):

The self parameter is the place where Python passes the current object.

You can think of it like this:

my_robot.beep()
      ↓
Python automatically passes my_robot
      ↓
Robot.beep(my_robot)
      ↓
             self
              ↓
        "this robot"

So when you forget self, Python is essentially saying:

“I tried to give you the robot object, but your method doesn’t have a parameter to receive it!”

Optional Attributes

An optional attribute simply means that when you create a new object, you don’t have to provide that particular piece of information.

If you leave it out, Python uses a default value instead.

We actually used an optional attribute earlier in our BankAccount example.

Consider:

def __init__(self, owner, starting_balance=0.0):

Here:

  • owner is required.
  • starting_balance is optional.
  • If no starting balance is provided, Python uses 0.0.

For example:

alice_account = BankAccount("Alice", 100.0)

Alice starts with $100.

But:

bob_account = BankAccount("Bob")

Bob automatically starts with $0.

This is the basic idea behind optional attributes.

1. The “Default Value” Method

The most straightforward way to create an optional attribute is to give the parameter a default value inside __init__.

You use the equals sign (=) to specify the default.

class Dog:

    # name is REQUIRED.
    # collar_color is OPTIONAL and defaults to "Red".
    def __init__(self, name, collar_color="Red"):
        self.name = name
        self.collar_color = collar_color


# We only provide the name.
# Python automatically uses "Red".
dog_1 = Dog("Buddy")

print(f"{dog_1.name} has a {dog_1.collar_color} collar.")
# Buddy has a Red collar.


# We provide both values.
# Python uses "Blue" instead of the default.
dog_2 = Dog("Daisy", "Blue")

print(f"{dog_2.name} has a {dog_2.collar_color} collar.")
# Daisy has a Blue collar.

The important idea is:

collar_color="Red"

means:

“If the user doesn’t provide a collar color, use Red.”

But if the user does provide a value:

Dog("Daisy", "Blue")

Python uses "Blue" instead.

2. The None Method — When Information Is Missing

Sometimes an attribute is optional because the information might not exist yet.

In Python, we can use the special value None to represent:

“There is currently no value.”

For example, imagine creating a user profile where a phone number is optional.

class UserProfile:

    # phone_number is optional.
    # If no number is provided, it is set to None.
    def __init__(self, username, phone_number=None):
        self.username = username
        self.phone_number = phone_number

    def show_profile(self):
        print(f"User: {self.username}")

        # Check whether a phone number was provided.
        if self.phone_number is None:
            print("Phone: No number provided.")
        else:
            print(f"Phone: {self.phone_number}")


# Create a user without a phone number
user_1 = UserProfile("CoolSkater99")

user_1.show_profile()

The output would be:

User: CoolSkater99
Phone: No number provided.

Here, None doesn’t mean that the phone number is zero or an empty string.

It means:

“No phone number has been provided.”

⚠️ The Golden Rule of Optional Attributes

When defining your __init__ method, all required parameters must come before optional parameters.

✅ Correct

def __init__(self, name, age, color="Brown"):

Here:

  • name is required.
  • age is required.
  • color is optional.

❌ Incorrect

def __init__(self, color="Brown", name, age):

This causes a SyntaxError because Python does not allow a required parameter to appear after a parameter with a default value.

A simple rule to remember is:

Required first, optional last.

Flexible Classes with *args and **kwargs

Sometimes, when you build a class, you don’t know exactly how much information the user will provide.

Imagine creating a Pizza class.

One customer might order:

Medium + Extra Cheese

while another customer might order:

Large + Pepperoni + Sausage + Onions + Peppers

It would be inconvenient to create a separate parameter for every possible topping.

Python gives us two powerful tools for handling an unlimited number of arguments:

  • *args
  • **kwargs

The magic is in the asterisks (* and **).

The names args and kwargs are simply common naming conventions. They are not special keywords.

For example, these work the same way:

*args
*toppings
*items

and:

**kwargs
**options
**settings

The asterisks are what matter.

1. *args — The Grab Bag

*args allows you to pass any number of regular, unnamed arguments to a function or class.

Python collects all those extra arguments and stores them in a tuple.

A tuple is similar to a list, except that its contents cannot normally be changed after it is created.

Think of *args like calling out pizza toppings:

“Pepperoni, onions, olives!”

These are individual values without labels.

Example: Pizza with Any Number of Toppings

class Pizza:

    # size is required.
    # *args catches all additional unnamed arguments.
    def __init__(self, size, *args):
        self.size = size
        self.toppings = args

    def describe(self):
        print(f"A {self.size} pizza with:")

        for topping in self.toppings:
            print(f"- {topping}")


# One topping
cheese_pizza = Pizza("Medium", "Extra Cheese")


# Four toppings
supreme = Pizza(
    "Large",
    "Pepperoni",
    "Sausage",
    "Onions",
    "Peppers"
)

supreme.describe()

The *args parameter collects the toppings into a tuple.

Conceptually:

args
 ↓
("Pepperoni", "Sausage", "Onions", "Peppers")

The output would be:

A Large pizza with:
- Pepperoni
- Sausage
- Onions
- Peppers

2. **kwargs — The Custom Order Form

**kwargs stands for Keyword Arguments.

It allows you to pass any number of labeled arguments using the name=value format.

Python collects these labeled values into a dictionary.

Think of **kwargs as filling out a custom order form:

crust = thin
sauce = spicy
well_done = True

Each value has a label, or key.

Example: A Flexible Smartphone Class

class SmartPhone:

    # brand is required.
    # **kwargs catches all custom specifications.
    def __init__(self, brand, **kwargs):
        self.brand = brand

        # kwargs is a dictionary.
        self.specs = kwargs

    def show_specs(self):
        print(f"--- {self.brand} Phone ---")

        for key, value in self.specs.items():
            print(f"{key}: {value}")


# We can provide any number of custom specifications.
my_phone = SmartPhone(
    "Apple",
    storage="256GB",
    color="Midnight",
    has_headphone_jack=False
)

my_phone.show_specs()

Conceptually, kwargs contains:

{
    "storage": "256GB",
    "color": "Midnight",
    "has_headphone_jack": False
}

The output would be:

--- Apple Phone ---
storage: 256GB
color: Midnight
has_headphone_jack: False

The key advantage is flexibility.

We don’t have to predict every possible specification when we create the class.

Putting *args and **kwargs Together

You can use both *args and **kwargs in the same class.

However, Python requires them to appear in a specific order.

The general pattern is:

  1. Regular required parameters
  2. *args
  3. **kwargs

Think of it as:

Required → Unnamed extras → Named extras

Example: Video Game Character

class VideoGameCharacter:

    def __init__(self, name, *args, **kwargs):
        self.name = name
        self.inventory = args
        self.stats = kwargs


hero = VideoGameCharacter(
    "Link",

    # *args
    "Sword",
    "Shield",

    # **kwargs
    health=100,
    magic=50
)

The information is stored like this:

name
 ↓
"Link"

inventory
 ↓
("Sword", "Shield")

stats
 ↓
{
    "health": 100,
    "magic": 50
}

So one object can contain three different types of information:

VideoGameCharacter
        │
        ├── name
        │     └── "Link"
        │
        ├── inventory
        │     └── ("Sword", "Shield")
        │
        └── stats
              ├── health = 100
              └── magic = 50

This makes classes extremely flexible.

*args vs. **kwargs

It is helpful to compare the two directly.

Feature *args **kwargs
Accepts Extra unnamed arguments Extra named arguments
Stored as Tuple Dictionary
Example "Sword", "Shield" health=100, magic=50
Think of it as A grab bag A custom order form
Asterisk * **

For example:

*args

might collect:

("Sword", "Shield", "Potion")

while:

**kwargs

might collect:

{
    "health": 100,
    "magic": 50,
    "level": 10
}

The Big Picture: Making Flexible Classes

We have now seen several ways to make classes flexible.

Required attributes

These must be provided:

def __init__(self, name, age):

Optional attributes with default values

These can be omitted:

def __init__(self, name, age=0):

Optional information using None

This represents information that may not exist:

def __init__(self, name, phone=None):

Unlimited unnamed information with *args

def __init__(self, name, *items):

Unlimited named information with **kwargs

def __init__(self, name, **options):

All together

def __init__(self, name, age=0, *args, **kwargs):

This gives us a powerful range of possibilities for designing classes.

A Real-World Example: Bank Accounts

Let’s apply everything we’ve learned to a practical example.

A bank account is something we can easily understand in the real world.

A bank account has:

Attributes — What the account has

  • Owner’s name
  • Current balance

Methods — What the account can do

  • Deposit money
  • Withdraw money
  • Check the balance

Let’s build a BankAccount class step by step.

Step 1: Create the Blueprint

First, we define our class and its constructor.

class BankAccount:

    # Create a new account
    def __init__(self, owner, starting_balance=0.0):
        self.owner = owner
        self.balance = starting_balance

The parameter:

starting_balance=0.0

provides a default value.

Therefore, if someone creates an account without specifying a starting balance, the account automatically starts with $0.00.

For example:

alice_account = BankAccount("Alice", 100.0)

Alice starts with $100.

But:

bob_account = BankAccount("Bob")

Bob starts with $0.

Step 2: Add Methods

Now let’s teach our BankAccount class how to handle money.

We will create three methods:

  1. deposit()
  2. withdraw()
  3. check_balance()
class BankAccount:

    def __init__(self, owner, starting_balance=0.0):
        self.owner = owner
        self.balance = starting_balance

    # ACTION 1: Deposit money
    def deposit(self, amount):

        if amount > 0:
            self.balance += amount
            print(
                f"Deposited ${amount}. "
                f"New balance is ${self.balance}."
            )
        else:
            print("You must deposit a positive amount!")

    # ACTION 2: Withdraw money
    def withdraw(self, amount):

        # Make sure there is enough money
        if amount > self.balance:
            print(
                f"Declined! You only have "
                f"${self.balance} in your account."
            )

        elif amount <= 0:
            print("You must withdraw a positive amount!")

        else:
            self.balance -= amount
            print(
                f"Withdrew ${amount}. "
                f"New balance is ${self.balance}."
            )

    # ACTION 3: Check the balance
    def check_balance(self):
        print(
            f"Account Owner: {self.owner} | "
            f"Current Balance: ${self.balance}"
        )

Notice that every method has self as its first parameter.

This is necessary because each method needs to know which particular bank account it is working with.

For example:

self.balance

means:

“The balance belonging to this particular account.”

Step 3: Create and Test Our Objects

Our blueprint is now complete.

Let’s create some actual bank account objects and test them.

# Create an account for Alice with $100
alice_account = BankAccount("Alice", 100.0)

# Create an account for Bob with $0
bob_account = BankAccount("Bob")

We now have two separate objects:

BankAccount class
       ↓
 ┌─────┴─────┐
 ↓           ↓
Alice       Bob
$100         $0

Let’s make some transactions.

# Alice deposits $50
alice_account.deposit(50)
# Deposited $50. New balance is $150.0.

# Alice withdraws $20
alice_account.withdraw(20)
# Withdrew $20. New balance is $130.0.

Now let’s see what happens when Bob tries to withdraw more money than he has.

bob_account.withdraw(500)
# Declined! You only have $0.0 in your account.

Finally, let’s check both accounts.

alice_account.check_balance()
# Account Owner: Alice | Current Balance: $130.0

bob_account.check_balance()
# Account Owner: Bob | Current Balance: $0.0

Putting Everything Together

Our BankAccount class combines data and actions into one organized structure.

                 BankAccount
                      │
          ┌───────────┴───────────┐
          │                       │
      Attributes               Methods
          │                       │
    ┌─────┴─────┐        ┌────────┼────────┐
    │           │        │        │        │
  owner      balance   deposit  withdraw  check_balance

Each object created from the class has its own attributes.

alice_account.owner
# Alice

alice_account.balance
# 130.0

while:

bob_account.owner
# Bob

bob_account.balance
# 0.0

The same class can therefore be used to create as many independent bank accounts as we need.

The Big Picture

The most important idea to remember is:

A class is a blueprint. An object is a specific instance created from that blueprint.

Classes allow us to package data and actions together.

OOP Concept Python Example Meaning
Class BankAccount Blueprint
Object alice_account A specific instance
Attribute self.balance Data belonging to the object
Method deposit() An action the object can perform
self self.balance Refers to the current object
Constructor __init__() Sets up a new object
Default value balance=0.0 Provides a fallback value
None phone=None Represents missing information
*args *toppings Collects extra unnamed arguments
**kwargs **options Collects extra named arguments

A useful mental model is:

             CLASS
          "The Blueprint"
                │
        ┌───────┼───────┐
        ↓       ↓       ↓
     Object   Object   Object
        │       │       │
        ↓       ↓       ↓
      Data    Data    Data
        +       +       +
     Actions  Actions  Actions

Once you understand classes, objects, attributes, methods, self, default values, None, *args, and **kwargs, you have learned the foundation for creating flexible Python classes.

Start with a blueprint, give each object its own data, and use methods to define what each object can do.
