1. Theoretical Running Time Formulation

The running time of the Insertion Sort algorithm is determined by calculating the time spent executing each individual line of pseudocode.

Line Insertion-Sort(A) cost times
1 for \(j = 2\) to \(A.length\) \(c_1\) \(n\)
2     \(key = A[j]\) \(c_2\) \(n - 1\)
3     // Insert \(A[j]\) into the sorted sequence \(A[1 \dots j - 1]\). \(0\) \(n - 1\)
4     \(i = j - 1\) \(c_4\) \(n - 1\)
5     while \(i > 0\) and \(A[i] > key\) \(c_5\) \(\sum_{j=2}^n t_j\)
6         \(A[i + 1] = A[i]\) \(c_6\) \(\sum_{j=2}^n (t_j - 1)\)
7         \(i = i - 1\) \(c_7\) \(\sum_{j=2}^n (t_j - 1)\)
8     \(A[i + 1] = key\) \(c_8\) \(n - 1\)

Constant Time Cost (\(c_i\))

  • \(c_i\) represents the constant time cost to execute line \(i\) exactly once.
  • Different operations (math, assignments, conditional checks) require slightly different processing times, hence unique costs (\(c_1, c_2, \dots\)).
  • Comments (e.g., Line 3) are ignored by the computer, resulting in a cost of \(0\).

Execution Frequency (The times column)

For an input array of size \(n\):

  • Outer loop header (Line 1): Runs \(n\) times (once per item, plus the final exit check).
  • Outer loop body (Lines 2, 4, 8): Runs \(n - 1\) times (one less than the header).
  • Inner while loop condition (Line 5): Runs \(\sum_{j=2}^n t_j\) times, where \(t_j\) is the number of condition checks during the \(j\)-th pass.
  • Inner while loop body (Lines 6, 7): Runs \(\sum_{j=2}^n (t_j - 1)\) times.

Total Running Time \(T(n)\)

To find the total running time, multiply the cost (\(c_i\)) by the execution frequency for each line, and sum the results:

\[ T(n) = c_1n + c_2(n-1) + c_4(n-1) + c_5 \sum_{j=2}^n t_j + c_6 \sum_{j=2}^n (t_j - 1) + c_7 \sum_{j=2}^n (t_j - 1) + c_8(n-1) \]

2. Concrete Example Trace: \(A = [3, 1, 2]\)

Let us trace the algorithm using an input size of \(n=3\) and hypothetical execution cycles for each \(c_i\).

Step A: Setting up Constants

Assume the following clock cycle costs per execution:

  • \(c_1 = 2\) cycles (checking for loop, incrementing \(j\))
  • \(c_2 = 1\) cycle (reading and assigning key)
  • \(c_4 = 1\) cycle (assigning \(i\))
  • \(c_5 = 3\) cycles (checking while conditions)
  • \(c_6 = 2\) cycles (shifting element right)
  • \(c_7 = 1\) cycle (decrementing \(i\))
  • \(c_8 = 1\) cycle (inserting key)

Step B: Tracing the Loops to Find \(t_j\)

  • Pass \(j = 2\) (Inserting 1 into \([3]\)): The condition is checked once successfully, and once failing (\(3>1\), then \(0>0\) fails). Result: \(t_2 = 2\) (loop body runs \(1\) time).

  • Pass \(j = 3\) (Inserting 2 into \([1, 3]\)): The condition is checked once successfully, and once failing (\(3>2\), then \(1>2\) fails). Result: \(t_3 = 2\) (loop body runs \(1\) time).

Step C: Computing Total Time \(T(3)\)

Substituting \(n=3, t_2=2, t_3=2\) into our frequencies:

  • Line 1: \(n = 3\) times
  • Lines 2, 4, 8: \(n-1 = 2\) times each
  • Line 5: \(t_2 + t_3 = 4\) times
  • Lines 6, 7: \((t_2-1) + (t_3-1) = 2\) times each

Multiplying by the \(c_i\) costs and summing:

\[ \begin{aligned} T(3) &= (c_1 \times 3) + (c_2 \times 2) + (c_4 \times 2) + (c_5 \times 4) + (c_6 \times 2) + (c_7 \times 2) + (c_8 \times 2) \\ &= (2 \times 3) + (1 \times 2) + (1 \times 2) + (3 \times 4) + (2 \times 2) + (1 \times 2) + (1 \times 2) \\ &= 6 + 2 + 2 + 12 + 4 + 2 + 2 \\ &= \mathbf{30 \text{ cycles}} \end{aligned} \]

Conclusion: For this unsorted array, it takes 30 cycles. If the array were already sorted (e.g., \([1, 2, 3]\)), the inner loop would fail immediately (\(t_2=1, t_3=1\)). This eliminates Lines 6 and 7, dropping the total running time to a much faster 18 cycles.

3. Best-Case and Worst-Case Scenarios

Even for inputs of the exact same size \(n\), the algorithm’s running time can vary drastically depending on how the initial items are arranged.

The Best-Case: Already Sorted

  • Scenario: The input array is already in the correct sorted order.
  • What happens: When the inner while loop checks if it needs to shift elements, it immediately finds they are in order (\(A[i] \le key\)).
  • Math impact: The condition is checked exactly once per pass (\(t_j = 1\)). The inner loop body never runs (\(t_j - 1 = 0\)).
  • Calculation: Substituting \(t_j = 1\) into our \(T(n)\) formula gives:

\[ \begin{aligned} T(n) &= c_1n + c_2(n-1) + c_4(n-1) + c_5(n-1) + c_8(n-1) \\ &= (c_1 + c_2 + c_4 + c_5 + c_8)n - (c_2 + c_4 + c_5 + c_8) \end{aligned} \]

  • Resulting Time: We can express this running time as \(T(n) = \mathbf{an + b}\) (where \(a\) and \(b\) are constants), which is a fast, linear function of \(n\).

The Worst-Case: Reverse Sorted

  • Scenario: The input array is completely backward (decreasing order).
  • What happens: The inner while loop must shift every new element all the way to the very front, comparing it against every single item in the already-sorted portion.
  • Math impact: The loop condition is checked \(j\) times per pass (\(t_j = j\)).
  • Applying Summations: We replace the sums in our \(T(n)\) formula using standard math rules:

\[ \sum_{j=2}^n j = \frac{n(n+1)}{2} - 1 \quad \text{and} \quad \sum_{j=2}^n (j-1) = \frac{n(n-1)}{2} \]

  • Calculation: Substituting these formulas into our \(T(n)\) equation gives:

\[ \begin{aligned} T(n) &= c_1n + c_2(n-1) + c_4(n-1) + c_5\left(\frac{n(n+1)}{2} - 1\right) \\ &\quad + c_6\left(\frac{n(n-1)}{2}\right) + c_7\left(\frac{n(n-1)}{2}\right) + c_8(n-1) \\ &= \left(\frac{c_5}{2} + \frac{c_6}{2} + \frac{c_7}{2}\right)n^2 + \left(c_1 + c_2 + c_4 + \frac{c_5}{2} - \frac{c_6}{2} - \frac{c_7}{2} + c_8\right)n - (c_2 + c_4 + c_5 + c_8) \end{aligned} \]

  • Resulting Time: We can express this worst-case time as \(T(n) = \mathbf{an^2 + bn + c}\) (where \(a, b,\) and \(c\) are constants), which is a significantly slower, quadratic function of \(n\).
